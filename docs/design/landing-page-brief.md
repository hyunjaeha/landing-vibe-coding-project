# 랜딩 페이지 섹션 구조

기준 문서:

- `docs/product/mvp-scope.md`
- `docs/product/user-flow.md`

## 문서 역할

이 문서는 방문자 랜딩 페이지를 화면으로 설계하기 위한 섹션 구조, 문구 기준, 디자인 토큰, 반응형 기준, 접근성 기준, 폼 상태를 정리합니다.

- 이 문서에 쓰는 내용: 랜딩 섹션, CTA 문구, UI 요소, 모바일 주의점, 디자인 토큰, 이미지 기준, 폼 상태
- 이 문서에 쓰지 않는 내용: 제품 기능 범위 결정, 관리자 구현 구조, Supabase 스키마, 운영자 처리 절차 상세

관련 상세 문서:

- 제품 범위와 PRD: `docs/product/mvp-scope.md`
- 사용자 흐름: `docs/product/user-flow.md`
- 구현 아키텍처: `docs/engineering/architecture.md`
- 운영 기준: `docs/operations/operating-guide.md`

## 설계 원칙

- 방문자가 워크숍 정보를 확인한 뒤 문의 폼을 제출하는 흐름에 집중합니다.
- CTA는 결제, 예약 확정, 할인, 마감 압박을 유도하지 않고 문의 제출로만 연결합니다.
- 모바일에서 핵심 정보, 일정, 문의 폼을 빠르게 확인할 수 있게 구성합니다.
- 개인정보 수집 동의, 보관 기준, 민감정보 입력 방지 안내를 문의 폼 주변에 명확히 표시합니다.

## 섹션 구조

| 순서 | 섹션 | 목적 | 표시할 텍스트 | 필요한 UI 요소 | 모바일에서 주의점 |
| --- | --- | --- | --- | --- | --- |
| 1 | 첫 화면 | 방문자가 어떤 워크숍인지 즉시 이해하고 문의 흐름으로 이동하게 합니다. | 워크숍명, 한 줄 소개, 대상자 요약, `문의하기` | 제목, 짧은 소개문, 핵심 정보 2~3개, 문의 폼 이동 버튼 | 첫 화면 안에서 워크숍명과 문의 버튼이 보이게 합니다. 장소와 가격은 바로 아래 요약 정보나 일정 섹션에서 보강해 첫 화면이 과밀해지지 않게 합니다. |
| 2 | 워크숍 소개 | 워크숍의 내용과 참여 대상을 설명해 문의 전 기본 판단을 돕습니다. | 진행 방식, 소요 시간, 이런 분께 맞아요, 준비물 | 설명 리스트, 대상자 리스트, 준비물 안내 | 긴 문단보다 짧은 항목형 문장으로 구성합니다. 준비물은 한 줄씩 분리해 읽기 쉽게 표시합니다. |
| 3 | 일정 안내 | 방문자가 가능한 일정과 상태를 확인하고 문의 폼에서 선택할 희망 일정을 이해하게 합니다. | 날짜, 시간, 모집 인원, 장소, 가격, 신청 가능 상태 | 일정 카드 또는 리스트, 상태 배지, 문의 폼으로 이동 버튼, 선택한 일정이 문의 폼에 반영되는 동작 | 일정 카드는 한 화면에 1개씩 세로 배치합니다. 마감 일정은 색상만으로 구분하지 않고 `마감` 문구를 함께 표시합니다. 일정 선택이 예약 확정처럼 보이지 않게 합니다. |
| 4 | 장소 및 참여 안내 | 오프라인 참여에 필요한 기본 정보를 확인하게 합니다. | 상세 주소, 외부 지도 링크, 이동 안내, 시작 전 도착 권장 시간, 준비물, 문의 전 확인 사항 | 주소 텍스트, 외부 지도 링크, 준비물 리스트, 유의사항 리스트 | 지도 임베드는 3일 MVP 범위에서 제외하고 주소 텍스트와 외부 지도 링크로 제한합니다. 주소가 길 경우 접히지 않게 줄바꿈합니다. |
| 5 | 문의 폼 | 방문자가 예약 의향 또는 질문을 제출하게 합니다. | 이름, 전화번호, 희망 일정, 참여 인원, 문의 내용(선택), 개인정보 수집 동의, 민감정보 입력 금지 짧은 문구, `문의 제출` | 텍스트 입력, 전화번호 입력, 일정 선택, 참여 인원 선택 또는 숫자 입력, 문의 내용 입력, 개인정보 동의 체크박스, 제출 버튼, 필수값 오류 메시지, 전화번호 형식 안내 | 입력 필드는 한 열로 배치합니다. 제출 버튼은 폼 하단에 고정하지 않고 입력 완료 후 자연스럽게 보이게 합니다. 오류 문구는 해당 입력 항목 바로 아래에 표시합니다. |
| 6 | 문의 제출 결과 메시지 | 문의 제출 후 방문자가 다음 행동을 이해하게 합니다. | 문의가 접수되었습니다, 운영자가 확인 후 연락드립니다, 다시 시도하기 | 성공 메시지, 실패 메시지, 다시 시도 버튼 또는 폼 유지 | 독립 섹션이 아니라 문의 폼의 제출 상태로 다룹니다. 제출 실패 시 입력값을 유지합니다. 성공 메시지는 예약 확정처럼 보이지 않게 `접수`와 `확인 후 연락`으로 표현합니다. |
| 7 | 하단 안내 | 개인정보와 서비스 범위를 명확히 안내합니다. | 개인정보 수집 목적, 보관 기간, 삭제 요청 방법, 결제/예약 확정은 별도 연락으로 진행 | 개인정보 안내 텍스트, 삭제 요청 연락처 또는 안내 문구, 범위 안내 | 작은 글씨라도 터치 확대 없이 읽을 수 있어야 합니다. 문의 폼의 짧은 민감정보 안내와 역할이 겹치지 않도록 보관/삭제 기준 중심으로 정리합니다. |

## CTA 문구 기준

사용 가능한 CTA:

- 문의하기
- 문의 폼으로 이동
- 문의 제출
- 다시 시도하기

사용하지 않을 CTA:

- 지금 예약 확정하기
- 바로 결제하기
- 선착순 마감
- 마지막 기회
- AI가 예약을 도와드립니다

## 화면 상태

| 화면 | 정상 상태 | 예외 상태 |
| --- | --- | --- |
| 첫 화면 | 페이지 로딩 중, 정상 표시 | 로딩 실패 |
| 일정 안내 | 일정 있음 | 일정 없음, 마감 일정 |
| 문의 폼 | 기본 입력 상태, 기본 안내 문구 표시, 수집 목적/보관 기간/삭제 요청 안내 표시, 전화번호 형식 안내 | 필수값 누락, 개인정보 동의 누락 |
| 문의 제출 결과 메시지 | 제출 중, 제출 성공 | 제출 실패 |
| 접수 완료 메시지 | 접수 완료 | 새 문의가 필요한 경우에만 폼으로 돌아가기 |

## 디자인 토큰

### 색상

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `color.background` | `#FAFAF7` | 전체 페이지 배경 |
| `color.surface` | `#FFFFFF` | 폼, 일정 카드, 안내 영역 배경 |
| `color.surfaceMuted` | `#F1F5F2` | 보조 안내 박스, 하단 안내 배경 |
| `color.warmSurface` | `#F6EFE4` | 이미지 캡션 배경, 부드러운 보조 배경 |
| `color.textPrimary` | `#111827` | 제목, 주요 본문 |
| `color.textSecondary` | `#374151` | 설명, 보조 정보 |
| `color.textMuted` | `#6B7280` | 캡션, 개인정보 안내 |
| `color.border` | `#D7DAD2` | 카드, 입력 필드, 필요한 구분선 |
| `color.primary` | `#1F6F5B` | 문의 CTA, 활성 상태 |
| `color.primaryHover` | `#185746` | CTA hover 또는 pressed |
| `color.accent` | `#8A5A00` | 상태 배지, 보조 강조 |
| `color.warning` | `#8A5A00` | 마감 임박, 주의 안내 |
| `color.error` | `#B42318` | 필수값 누락, 제출 실패 |
| `color.success` | `#1F6F5B` | 접수 성공 |

색상 사용 기준:

- 전체 화면은 오프화이트 배경과 흰색 표면을 기본으로 하고, CTA는 딥 그린으로 제한해 실제 사진과 충돌하지 않게 합니다.
- 상태 배지는 색상만으로 의미를 전달하지 않고 `문의 가능`, `마감 임박`, `마감` 텍스트를 함께 표시합니다.
- CTA는 `color.primary`만 사용하고, 경고색이나 빨간색으로 마감 압박을 만들지 않습니다.
- 마감 상태는 색상뿐 아니라 `마감` 텍스트를 반드시 함께 표시합니다.

접근성 기준:

- 본문 텍스트와 배경의 명도 대비는 WCAG AA 기준인 4.5:1 이상을 목표로 합니다.
- 버튼 텍스트는 흰색을 사용하고 `color.primary` 배경과 충분한 대비를 유지합니다.
- 비활성 또는 보조 텍스트도 3:1 미만의 낮은 대비가 되지 않도록 `color.textMuted`보다 흐린 색을 사용하지 않습니다.
- 포커스 상태는 색상 변화만으로 처리하지 않고 2px 이상의 명확한 외곽선 또는 링을 함께 사용합니다.

### 이미지 사용 기준

| 영역 | 이미지 방향 | 권장 소스 |
| --- | --- | --- |
| 첫 화면 이미지 | 실제 사람들이 노트북을 놓고 협업하는 밝은 워크숍 분위기 | Unsplash 무료 이미지 |
| 장소 및 참여 안내 이미지 | 오프라인 수업, 실습, 학습 공간이 드러나는 이미지 | Unsplash 무료 이미지 |

이미지 기준:

- 실제 사진을 사용하고 추상 일러스트나 빈 그래픽 플레이스홀더로 대체하지 않습니다.
- 어둡거나 흐릿한 이미지는 피하고, 노트북, 책상, 참여자, 학습 공간이 명확히 보이는 이미지를 사용합니다.
- 인물 사진 위에는 중요한 본문을 직접 올리지 않고, 필요한 경우 짧은 캡션만 표면색 배경 위에 표시합니다.
- 이미지 출처는 디자인 파일 또는 작업 문서에서 추적 가능하도록 남깁니다.

### 타이포그래피

| 토큰 | 크기 | 줄 높이 | 용도 |
| --- | --- | --- | --- |
| `font.display` | 32px | 40px | 첫 화면 워크숍명 |
| `font.heading` | 24px | 32px | 섹션 제목 |
| `font.subheading` | 18px | 28px | 카드 제목, 일정 제목 |
| `font.body` | 16px | 26px | 본문, 입력 라벨 |
| `font.caption` | 13px | 20px | 보조 설명, 개인정보 안내 |

타이포그래피 기준:

- 모바일에서 제목이 두 줄을 넘어가면 문구를 줄이고 글자 크기를 임의로 크게 키우지 않습니다.
- 버튼과 입력 필드 안의 텍스트는 `font.body`를 기준으로 읽기 쉽게 유지합니다.
- 글자 간격은 기본값을 사용하고 과한 자간 조정은 하지 않습니다.

### 간격과 형태

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `space.1` | 4px | 작은 요소 간격 |
| `space.2` | 8px | 라벨과 입력 필드 간격 |
| `space.3` | 12px | 카드 내부 보조 간격 |
| `space.4` | 16px | 기본 섹션 내부 간격 |
| `space.6` | 24px | 카드 간격, 폼 그룹 간격 |
| `space.8` | 32px | 섹션 상하 간격 |
| `radius.sm` | 6px | 입력 필드, 상태 배지 |
| `radius.md` | 8px | 일정 카드, 안내 박스 |
| `shadow.card` | `0 1px 3px rgba(31, 41, 51, 0.08)` | 카드의 약한 입체감 |

형태 기준:

- 카드 radius는 8px 이하로 유지합니다.
- 섹션 전체를 카드처럼 감싸지 않고, 일정 카드와 폼처럼 실제로 구분이 필요한 요소에만 카드 스타일을 사용합니다.
- 카드 내부의 배지, 버튼, 입력 필드가 이미 자체 경계를 가지는 경우 부모 카드와 자식 요소에 중복 border를 과하게 겹치지 않습니다.
- 헤더, 푸터, 섹션 컨테이너에는 기본적으로 border를 쓰지 않고, 구분이 필요한 입력 필드와 개별 카드에만 1px border를 사용합니다.
- CTA 버튼은 높이 48px 이상으로 만들어 터치하기 쉽게 합니다.

## 반응형 기준

| 기준 | 화면 너비 | 레이아웃 |
| --- | --- | --- |
| 모바일 | 360px 이상 | 모든 섹션 1열, 일정 카드 1개씩 세로 배치, 입력 필드 전체 너비 |
| 큰 모바일 | 430px 이상 | 핵심 정보 요약을 2열까지 허용하되 폼은 1열 유지 |
| 태블릿 | 768px 이상 | 소개/장소 안내는 2열 배치 가능, 일정 카드는 2열 가능 |
| 데스크톱 | 1024px 이상 | 본문 최대 너비 960px, 첫 화면과 문의 폼은 과하게 넓어지지 않도록 중앙 정렬 |

반응형 주의점:

- 360px 화면에서 가로 스크롤이 생기면 안 됩니다.
- 문의 폼의 라벨, 입력 필드, 오류 문구는 세로로 쌓습니다.
- 일정 카드 안의 날짜, 시간, 장소, 가격은 줄바꿈이 가능해야 합니다.
- 첫 화면 CTA는 화면 하단 고정 버튼으로 만들지 않고 콘텐츠 흐름 안에 둡니다.
- 데스크톱에서도 첫 화면 높이를 과하게 키우지 않아 다음 섹션 일부가 보이게 합니다.

## 컴포넌트 기준

### 버튼

| 상태 | 표시 기준 |
| --- | --- |
| 기본 | `문의하기`, `문의 폼으로 이동`, `문의 제출` CTA에 사용합니다. |
| hover/pressed | 색상만 약하게 어둡게 바꾸고 크기 변화는 주지 않습니다. |
| disabled | 필수값 또는 개인정보 동의가 누락된 경우 제출 버튼에 적용할 수 있습니다. |
| loading | 문의 제출 중 버튼 텍스트를 `제출 중`으로 바꾸고 중복 제출을 막습니다. |

버튼 문구는 문의 제출 흐름으로만 연결합니다. 예약 확정, 결제, 할인, 마감 압박 문구는 사용하지 않습니다.

### 일정 카드

필수 표시 요소:

- 날짜
- 시간
- 모집 인원
- 장소
- 가격
- 신청 가능 상태
- 문의 폼으로 이동 버튼

상태 표시:

- 신청 가능: `문의 가능`
- 마감 임박: `마감 임박`
- 마감: `마감`
- 일정 없음: 카드 대신 준비 중 안내 문구 표시

주의점:

- `마감 임박`은 정보 전달용으로만 사용하고 압박성 문구를 붙이지 않습니다.
- 일정 카드를 누르는 동작은 예약 확정이 아니라 문의 폼의 희망 일정 선택으로만 연결합니다.

### 안내 박스

사용 위치:

- 민감정보 입력 금지 안내
- 개인정보 수집 목적/보관 기간/삭제 요청 안내
- 일정 없음 또는 제출 실패 안내

표시 기준:

- 안내 박스는 짧은 제목과 1~2줄 설명으로 제한합니다.
- 오류 안내는 `color.error`를 사용하되 위협적으로 보이지 않게 명확한 해결 방법을 함께 제시합니다.

## 문의 폼 상세 상태

| 상태 | 조건 | 화면 처리 |
| --- | --- | --- |
| 기본 | 사용자가 아직 입력 전이거나 입력 중인 상태 | 라벨, 입력 필드, 도움말 문구를 표시합니다. |
| 필수값 누락 | 이름, 전화번호, 희망 일정 중 하나가 비어 있음 | 해당 필드 아래에 오류 문구를 표시하고 제출을 막습니다. |
| 전화번호 형식 안내 | 전화번호가 너무 짧거나 숫자/하이픈 외 문자가 포함됨 | `연락 가능한 전화번호를 입력해 주세요` 안내를 표시합니다. |
| 개인정보 동의 누락 | 개인정보 수집 동의 체크박스가 비어 있음 | 체크박스 아래에 동의가 필요하다는 안내를 표시하고 제출을 막습니다. |
| 제출 중 | Supabase 저장 요청을 보내는 중 | 제출 버튼을 비활성화하고 `제출 중` 상태를 표시합니다. |
| 제출 성공 | Supabase 저장이 완료됨 | `문의가 접수되었습니다. 운영자가 확인 후 연락드립니다.` 메시지를 표시합니다. |
| 제출 실패 | 저장 요청 실패 또는 네트워크 오류 | 입력값을 유지하고 `문의 접수에 실패했습니다. 잠시 후 다시 시도해 주세요.` 메시지를 표시합니다. |

필드별 기준:

| 필드 | 필수 여부 | UI 기준 |
| --- | --- | --- |
| 이름 | 필수 | 한 줄 텍스트 입력 |
| 전화번호 | 필수 | 전화번호 입력, 숫자와 하이픈 입력 허용 |
| 희망 일정 | 필수 | 일정 선택 드롭다운 또는 라디오 목록 |
| 참여 인원 | 선택 | 숫자 입력 또는 간단한 선택 목록 |
| 문의 내용 | 선택 | 여러 줄 입력, 민감정보 입력 금지 안내 표시 |
| 개인정보 수집 동의 | 필수 | 체크박스와 짧은 동의 문구 표시 |

폼 문구 예시:

- 이름: `이름`
- 전화번호: `전화번호`
- 희망 일정: `희망 일정`
- 참여 인원: `참여 인원(선택)`
- 문의 내용: `문의 내용(선택)`
- 민감정보 안내: `건강 정보, 주민등록번호, 결제 정보 등 민감한 개인정보는 입력하지 마세요.`
- 개인정보 동의: `문의 응대를 위해 이름과 전화번호를 수집하는 데 동의합니다.`

## 제외할 표현과 기능

- 예약 확정처럼 보이는 문구를 사용하지 않습니다.
- 결제, 환불, 쿠폰, 정산 기능을 암시하지 않습니다.
- 회원가입, 로그인, 마이페이지 진입을 만들지 않습니다.
- 실시간 잔여석 자동 차감처럼 보이는 표현을 사용하지 않습니다.
- 문의 내용에 건강 정보, 주민등록번호, 결제 정보 등 민감한 개인정보 입력을 유도하지 않습니다.
