# 아키텍처 기준

이 문서는 구현 구조와 기술 경계를 정의합니다. 제품 범위는 `docs/product/mvp-scope.md`, 사용자 흐름은 `docs/product/user-flow.md`, 디자인 기준은 `docs/design/landing-page-brief.md`를 기준으로 합니다.

## 문서 역할

- 이 문서는 코드 구조, 데이터 흐름, Supabase 연동, 관리자 접근 보호, 환경변수 기준을 다룹니다.
- 기능 요구사항의 원문은 반복하지 않고 `docs/product/mvp-scope.md`를 참조합니다.
- 디자인 토큰과 UI 세부 상태는 반복하지 않고 `docs/design/landing-page-brief.md`를 참조합니다.
- 운영자가 실제로 처리할 업무 절차는 `docs/operations/operating-guide.md`를 참조합니다.

## 구현 범위

3일 MVP 아키텍처는 다음 경계 안에서 설계합니다.

- 공개 랜딩 페이지
- 문의 제출 폼
- Supabase 단일 문의 테이블 저장
- 관리자 접근 보호가 있는 최소 문의 목록 화면
- 정적 운영 체크리스트 표시
- 모바일 우선 반응형 화면

다음 구조는 MVP에서 제외합니다.

- 결제, 환불, 쿠폰, 정산
- 회원가입, 로그인, 마이페이지
- 다중 관리자 권한 관리
- 검색, 통계, 그래프가 있는 고급 관리자 대시보드
- 문자, 이메일, 카카오톡 자동 발송
- AI 자동 예약 확정 또는 자동 고객 응대

## 권장 화면 구조

| 화면 | 책임 | 주요 데이터 |
| --- | --- | --- |
| 랜딩 페이지 | 워크숍 정보, 일정, 장소, 문의 폼을 표시합니다. | 워크숍 소개, 일정 목록, 장소 정보 |
| 문의 제출 API 또는 서버 액션 | 문의 입력값을 검증하고 Supabase에 저장합니다. | 이름, 전화번호, 희망 일정, 참여 인원, 문의 내용, 개인정보 동의 |
| 관리자 접근 화면 | 단일 운영자 접근 키 또는 비밀번호를 확인합니다. | 관리자 접근 키 |
| 관리자 문의 목록 | Supabase 문의 목록을 최신순으로 표시합니다. | 문의 목록, 접수 시간 |
| 운영 체크리스트 영역 | 워크숍 준비 항목을 정적으로 표시합니다. | 정적 체크리스트 항목 |

## 데이터 흐름

1. 방문자가 랜딩 페이지에서 워크숍 정보를 확인합니다.
2. 방문자가 문의 폼에 필수값을 입력하고 개인정보 수집 동의에 체크합니다.
3. 서버 측 제출 처리에서 필수값과 개인정보 동의 여부를 검증합니다.
4. 검증을 통과한 문의만 Supabase 문의 테이블에 저장합니다.
5. 저장 성공 시 접수 완료 메시지를 표시합니다.
6. 운영자는 접근 보호를 통과한 뒤 Supabase 문의 목록을 확인합니다.

## Supabase 기준

문의 데이터는 `docs/product/mvp-scope.md`의 데이터 요구사항을 기준으로 단일 테이블에 저장합니다.

권장 테이블 책임:

- 문의 접수 데이터만 저장합니다.
- 운영 체크리스트 체크 상태는 저장하지 않습니다.
- 결제 상태, 예약 확정 상태, 자동 발송 상태는 저장하지 않습니다.

권장 필드:

- `id`
- `name`
- `phone`
- `preferredSchedule`
- `participantCount`
- `message`
- `privacyConsent`
- `createdAt`

## 보안 경계

- Supabase 서비스 역할 키와 관리자 비밀 값은 브라우저 코드에 포함하지 않습니다.
- 공개 클라이언트에서 사용할 수 있는 키와 서버 전용 키를 구분합니다.
- 문의 목록 조회는 관리자 접근 보호를 통과한 경로에서만 수행합니다.
- 관리자 화면은 공개 랜딩 페이지와 URL 또는 라우트 수준에서 분리합니다.
- 단일 관리자 접근 보호는 MVP 범위에서 충분하지만, 다중 권한 관리는 만들지 않습니다.

## 입력 검증 기준

- 이름, 전화번호, 희망 일정, 개인정보 수집 동의는 서버 측에서도 다시 확인합니다.
- 전화번호는 연락 가능한 형식인지 최소 검증합니다.
- 문의 내용은 선택값이며 비어 있어도 저장할 수 있습니다.
- 건강 정보, 주민등록번호, 결제 정보 등 민감정보 입력을 유도하지 않습니다.
- 제출 실패 시 입력값을 유지하고 다시 시도 안내를 표시할 수 있게 설계합니다.

## 상태 처리 기준

| 상태 | 처리 기준 |
| --- | --- |
| 일정 없음 | 랜딩 페이지에서 준비 중 안내를 표시하고 문의 폼은 사용할 수 있게 둡니다. |
| 마감 일정 | `마감` 텍스트를 표시하고 예약 확정처럼 보이지 않게 합니다. |
| 문의 제출 중 | 중복 제출을 막습니다. |
| 문의 제출 성공 | 접수 완료와 운영자 확인 후 연락 문구를 표시합니다. |
| 문의 제출 실패 | 실패 안내와 다시 시도 방법을 표시합니다. |
| 관리자 접근 실패 | 문의 목록을 표시하지 않습니다. |
| 문의 없음 | 빈 화면 대신 접수된 문의가 없다는 안내를 표시합니다. |

## 문서 동기화 기준

- 기능 요구사항이 바뀌면 `mvp-scope.md`를 먼저 수정하고 이 문서의 구조 영향만 갱신합니다.
- 화면 흐름이 바뀌면 `user-flow.md`를 먼저 수정하고 라우트 또는 데이터 흐름 영향만 이 문서에 반영합니다.
- 디자인 기준이 바뀌면 `landing-page-brief.md`를 먼저 수정하고 구현상 필요한 제약만 이 문서에 반영합니다.
- 검증 기준이 바뀌면 `quality-gates.md`에 반영합니다.
