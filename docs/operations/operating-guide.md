# 운영 기준

## 문서 역할

이 문서는 소규모 오프라인 워크숍 예약/문의 랜딩 서비스를 배포한 뒤 운영자가 실제로 확인하고 처리할 기준을 정리합니다.

- 이 문서에 쓰는 내용: 문의 확인, 수동 연락, 정적 운영 체크리스트, 개인정보 보관/삭제 처리, 범위 밖 요청 대응
- 이 문서에 쓰지 않는 내용: 제품 요구사항 원문, 화면 디자인 토큰, Supabase 스키마 상세, 자동 예약/결제 기능

상세 기준 문서:

- 제품 범위: `docs/product/mvp-scope.md`
- 사용자 흐름: `docs/product/user-flow.md`
- 구현 경계: `docs/engineering/architecture.md`
- 품질 검증: `docs/engineering/quality-gates.md`

## 운영 원칙

- 문의 제출은 예약 확정이 아니라 운영자가 확인할 접수 상태로 봅니다.
- 참여 가능 여부, 결제, 최종 예약 확정은 운영자가 전화 또는 별도 연락 채널로 수동 안내합니다.
- 운영 체크리스트는 화면에 정적으로 표시하며, 체크 여부를 저장하지 않습니다.
- 자동 문자 발송, 자동 예약 확정, 결제, 다중 운영자 권한 관리는 3일 MVP 범위에서 제외합니다.
- 문의 내용에 민감정보가 포함된 경우 저장된 내용을 운영자가 확인한 뒤 불필요한 정보 삭제를 우선 처리합니다.

## 문의 확인 기준

| 항목 | 운영 기준 |
| --- | --- |
| 확인 주기 | 워크숍 모집 기간에는 하루 1회 이상 문의 목록을 확인합니다. |
| 확인 정보 | 이름, 전화번호, 희망 일정, 참여 인원, 문의 내용, 접수 시간을 확인합니다. |
| 우선 연락 대상 | 희망 일정이 임박했거나 문의 내용이 명확한 접수 건을 먼저 확인합니다. |
| 연락 방식 | 시스템 내 자동 발송 없이 전화 또는 운영자가 사용하는 별도 연락 채널로 수동 연락합니다. |
| 처리 기록 | MVP에서는 처리 상태 저장을 만들지 않습니다. 필요하면 운영자가 별도 메모 도구로 관리합니다. |

## 수동 연락 기준

운영자는 문의 확인 후 다음 내용을 수동으로 안내합니다.

1. 희망 일정의 참여 가능 여부
2. 정확한 장소와 도착 시간
3. 준비물과 참여 전 유의사항
4. 결제 또는 예약 확정이 필요한 경우 별도 절차
5. 개인정보 삭제 요청 방법

안내 문구는 예약이 이미 확정된 것처럼 표현하지 않습니다. 문의 단계에서는 `접수 확인`, `참여 가능 여부 안내`, `추가 안내 예정`과 같은 표현을 사용합니다.

## 정적 운영 체크리스트

관리자 화면에는 다음 체크리스트를 정적으로 표시할 수 있습니다.

| 구분 | 확인 항목 |
| --- | --- |
| 장소 | 장소 예약 여부, 주소 안내 정확성, 입장 방법 |
| 일정 | 날짜, 시작 시간, 소요 시간, 모집 인원 |
| 준비물 | 운영자 준비물, 참여자 준비물, 현장 비치 물품 |
| 연락 | 참여 가능 여부 안내, 사전 안내 메시지, 당일 안내 |
| 진행 | 시작 전 세팅, 출석 확인, 종료 후 후속 안내 |

체크 상태 저장, 담당자 배정, 알림 발송은 만들지 않습니다.

## 개인정보 보관 및 삭제 처리

| 항목 | 운영 기준 |
| --- | --- |
| 수집 목적 | 워크숍 문의 확인과 수동 연락 |
| 수집 항목 | 이름, 전화번호, 희망 일정, 참여 인원, 문의 내용, 개인정보 동의 여부, 접수 시간 |
| 보관 기간 | 워크숍 종료 후 운영자가 정한 짧은 기간만 보관하고, 불필요해지면 삭제합니다. |
| 삭제 요청 | 방문자가 삭제를 요청하면 Supabase 문의 데이터에서 해당 접수 건을 삭제합니다. |
| 민감정보 | 건강정보, 주민등록번호, 결제정보 등은 입력하지 않도록 안내하고, 발견 시 보관하지 않습니다. |

정확한 문구와 화면 표시 기준은 `docs/design/landing-page-brief.md`의 폼 상태 및 개인정보 안내 기준을 따릅니다.

## 범위 밖 요청 대응

| 요청 | MVP 대응 |
| --- | --- |
| 온라인 결제 | 별도 연락으로 안내하며 시스템에는 구현하지 않습니다. |
| 자동 예약 확정 | 운영자가 수동으로 확정 여부를 안내합니다. |
| 일정 변경 자동 반영 | MVP에서는 운영자가 일정 정보를 직접 수정합니다. |
| 문의 처리 상태 관리 | 별도 메모 도구를 사용하고, 시스템에는 저장하지 않습니다. |
| 여러 관리자 권한 관리 | 단일 관리자 접근 보호만 사용합니다. |

## 장애 또는 제출 실패 대응

- 방문자가 제출 실패를 문의하면 같은 정보를 별도 연락 채널로 받을 수 있게 안내합니다.
- Supabase 연결 문제로 문의 목록을 확인할 수 없으면 배포 환경변수와 Supabase 프로젝트 상태를 먼저 확인합니다.
- 장애 중 수집한 문의는 중복 저장 가능성이 있으므로 복구 후 이름, 전화번호, 접수 시간을 기준으로 중복 여부를 확인합니다.

## 문서 동기화 기준

- 운영 방식이 제품 범위를 바꾸면 `docs/product/mvp-scope.md`를 먼저 수정합니다.
- 운영 화면 상태가 바뀌면 `docs/product/user-flow.md`를 함께 확인합니다.
- 운영 검증 기준이 바뀌면 `docs/engineering/quality-gates.md`를 갱신합니다.
- 운영 기준을 다른 문서에 반복해서 쓰지 않고, 필요한 곳에서는 이 문서 경로만 참조합니다.
