# 소규모 오프라인 워크숍 예약/문의 랜딩 서비스 MVP 범위

## 문서 역할

이 문서는 서비스 정의, MVP 범위, PRD, 기능 요구사항, 비기능 요구사항의 단일 기준입니다.

- 이 문서에 쓰는 내용: 사용자 문제, 운영자 목표, 3일 안에 만들 범위, 만들지 않을 범위, 요구사항과 통과 기준
- 이 문서에 쓰지 않는 내용: 화면별 사용자 흐름, 랜딩 디자인 토큰, Supabase 구현 구조, 운영 절차 상세

- 랜딩 디자인 기준: `docs/design/landing-page-brief.md`

## 서비스 한 줄 설명

소규모 오프라인 워크숍의 일정, 장소, 내용, 신청 방법을 한 페이지에서 안내하고 예약 문의를 받을 수 있는 랜딩 서비스입니다.

## 주요 사용자 2명

1. 워크숍 참여자
   - 관심 있는 오프라인 워크숍의 일정, 장소, 가격, 준비물을 빠르게 확인하고 예약 가능 여부를 문의하려는 사람입니다.

2. 워크숍 운영자
   - 별도 예약 시스템 없이 워크숍 정보를 정리해 공개하고, 신청 의사가 있는 사람의 문의를 모아 응대하려는 사람입니다.

## 사용자가 해결하려는 문제

- 워크숍 정보가 SNS, 메신저, 포스터 등에 흩어져 있어 핵심 정보를 한 번에 확인하기 어렵습니다.
- 참여 가능 일정, 장소, 비용, 준비물, 신청 방법을 운영자에게 반복해서 물어봐야 합니다.
- 신청 전에 워크숍 분위기와 대상자를 확인하기 어려워 참여 결정을 미루게 됩니다.
- 문의 채널이 명확하지 않으면 예약 의사가 있어도 바로 행동으로 이어지기 어렵습니다.

## 운영자가 얻으려는 결과

- 워크숍 소개, 일정, 장소, 가격, 신청 방법을 한 페이지로 정리해 반복 설명을 줄입니다.
- 예약 전환 가능성이 있는 문의를 이름, 전화번호, 희망 일정, 문의 내용 형태로 수집합니다.
- 워크숍 상세 안내 링크를 SNS, 문자, 메신저에 공유해 홍보와 응대를 단순화합니다.
- 초기에는 자동 결제나 복잡한 예약 관리 없이 실제 수요와 문의 흐름을 확인합니다.

## 이번 3일 과정에서 만들 범위

- 워크숍 소개 랜딩 페이지
  - 워크숍명, 한 줄 소개, 대상자, 진행 방식, 소요 시간, 장소 안내를 표시합니다.

- 일정 및 신청 안내 영역
  - 운영자가 지정한 2~3개 워크숍 일정을 보여줍니다.
  - 각 일정의 날짜, 시간, 모집 인원, 장소, 가격을 표시합니다.

- 문의 및 예약 의향 접수 폼
  - 이름, 전화번호, 희망 일정, 문의 내용을 입력받습니다.
  - 개인정보 수집 동의를 받고 민감정보 입력 방지 안내를 표시합니다.
  - 제출 후 접수 완료 메시지를 보여줍니다.

- 운영자 확인용 최소 관리자 화면
  - 접수된 문의 목록을 운영자가 확인할 수 있는 간단한 화면을 만듭니다.
  - 이름, 전화번호, 희망 일정, 문의 내용, 접수 시간을 확인할 수 있게 합니다.
  - 단일 관리자 접근 보호를 적용해 공개 랜딩 페이지와 분리합니다.
  - 3일 과정에서는 검색, 통계, 권한 관리가 포함된 고급 대시보드가 아니라 접수 확인용 목록 화면까지를 범위로 둡니다.

- 운영 체크리스트
  - 워크숍 진행 전 운영자가 확인해야 할 준비 항목을 정리합니다.
  - 장소, 준비물, 참여자 연락, 안내 메시지, 당일 진행 확인 항목처럼 실제 오프라인 운영에 필요한 최소 항목을 포함합니다.
  - 3일 과정에서는 정적 체크리스트 표시로 제한하고 체크 상태 저장은 만들지 않습니다.

- 기본 배포
  - 외부 사용자가 접속 가능한 URL로 배포합니다.
  - 모바일에서 정보 확인과 문의 제출이 가능하도록 반응형 화면을 구성합니다.

## 이번 과정에서 만들지 않을 범위

- 온라인 결제, 환불, 쿠폰, 정산 기능
- 실시간 좌석 수 자동 차감 및 대기자 자동 배정
- 회원가입, 로그인, 마이페이지
- 검색, 통계, 권한 관리가 포함된 운영자용 고급 관리자 대시보드
- 캘린더 자동 연동
- 문자, 이메일, 카카오톡 자동 발송
- 다중 운영자 권한 관리
- 여러 워크숍 브랜드를 동시에 운영하는 복합 플랫폼 기능
- AI가 자동으로 예약을 확정하거나 고객 응대를 대신하는 기능

- [ ] Supabase 문의 테이블 구조 확정
- [ ] 운영자가 접수 내용을 확인할 최소 관리자 화면 구성 결정

# PRD

## 문서 목적

이 문서는 소규모 오프라인 워크숍 운영자가 3일 안에 배포 가능한 예약/문의 랜딩 서비스를 만들기 위한 제품 요구사항을 정의합니다.

## 제품 목표

- 참여자가 워크숍 정보를 한 화면에서 확인하고 문의를 남길 수 있게 합니다.
- 운영자가 반복 안내를 줄이고 예약 의향이 있는 문의를 모아 확인할 수 있게 합니다.
- 온라인 결제나 복잡한 예약 자동화 없이 실제 수요와 문의 흐름을 빠르게 검증합니다.

## 핵심 원칙

- 3일 안에 배포 가능한 범위로 제한합니다.
- 참여자의 정보 확인과 문의 제출을 우선합니다.
- 운영자에게는 접수 확인과 운영 준비에 필요한 최소 기능만 제공합니다.
- 자동 예약 확정, 결제, 고급 통계, 권한 관리는 제외합니다.

## 성공 기준

- 참여자는 모바일에서 워크숍 핵심 정보를 확인하고 문의 폼을 제출할 수 있습니다.
- 운영자는 접수된 문의 목록에서 이름, 전화번호, 희망 일정, 문의 내용, 접수 시간을 확인할 수 있습니다.
- 운영자는 워크숍 진행 전 확인해야 할 운영 체크리스트를 볼 수 있습니다.
- 서비스는 외부 사용자가 접근 가능한 URL로 배포됩니다.

## 기능 요구사항

| ID | 요구사항 | 통과 기준 |
| --- | --- | --- |
| FR-001 | 참여자가 워크숍명, 한 줄 소개, 대상자, 진행 방식, 소요 시간, 장소, 가격, 준비물을 확인할 수 있어야 합니다. | 모바일 첫 화면 또는 첫 화면 직후 영역에서 워크숍의 성격과 참여 조건을 이해할 수 있습니다. |
| FR-002 | 참여자가 문의 또는 신청 버튼을 통해 문의 폼으로 이동할 수 있어야 합니다. | 버튼을 누르면 문의 폼 영역으로 이동하거나 문의 폼을 바로 사용할 수 있습니다. |
| FR-003 | 운영자가 지정한 2~3개 워크숍 일정을 표시해야 합니다. | 각 일정에 날짜, 시간, 모집 인원, 장소, 가격, 신청 가능 상태 문구가 표시됩니다. |
| FR-004 | 일정이 없거나 마감된 경우에도 참여자가 상태를 이해할 수 있어야 합니다. | 일정이 없으면 준비 중 문구가 표시되고, 마감 일정은 마감 상태가 표시됩니다. |
| FR-005 | 참여자가 이름, 전화번호, 희망 일정, 문의 내용을 입력해 예약 의향 또는 문의를 제출할 수 있어야 합니다. | 필수값이 모두 입력되고 개인정보 수집 동의가 체크된 상태에서 제출하면 접수 완료 메시지가 표시됩니다. |
| FR-006 | 문의 폼의 필수값 누락을 방지해야 합니다. | 이름, 전화번호, 희망 일정, 개인정보 수집 동의 중 하나라도 비어 있으면 제출되지 않고 안내 문구가 표시됩니다. |
| FR-007 | 제출된 문의 데이터는 Supabase에 저장되어야 합니다. | 제출 후 Supabase 문의 테이블에 이름, 전화번호, 희망 일정, 문의 내용, 접수 시간이 저장됩니다. |
| FR-008 | 운영자는 최소 관리자 화면에서 Supabase에 저장된 문의 목록을 확인할 수 있어야 합니다. | 최신 문의가 목록 형태로 표시되고, 문의가 없으면 빈 상태 안내 문구가 표시됩니다. |
| FR-009 | 관리자 화면은 단일 운영자 접근 보호를 적용해야 합니다. | 관리자 화면은 공개 랜딩 페이지와 분리되고, 환경변수 기반 접근 키 또는 단일 관리자 비밀번호 없이는 문의 목록을 볼 수 없습니다. |
| FR-010 | 운영자는 워크숍 진행 전 정적 운영 체크리스트를 확인할 수 있어야 합니다. | 장소 예약, 준비물, 참여자 연락, 사전 안내 메시지, 당일 진행 순서, 비상 연락 또는 변경 공지 방식 항목이 표시되며 체크 상태 저장은 하지 않습니다. |
| FR-011 | 서비스는 외부 사용자가 접근 가능한 URL로 배포되어야 합니다. | 배포 URL에서 랜딩 페이지가 열리고 모바일에서 정보 확인과 문의 제출이 가능합니다. |
| FR-012 | 문의 내용 입력 영역에는 민감정보 입력 방지 안내를 표시해야 합니다. | 문의 내용 입력 근처에 건강 정보, 주민등록번호, 결제 정보 등 민감한 개인정보를 입력하지 말라는 안내가 표시됩니다. |

## 상태 및 예외 처리

### 문의 폼

- 필수값 누락: 제출하지 않고 해당 입력 항목 근처에 안내 문구를 표시합니다.
- 잘못된 전화번호 형식: 숫자와 하이픈 중심의 기본 형식 안내를 제공하되, 엄격한 검증보다 연락 가능한 값 입력을 우선합니다.
- 제출 성공: 접수 완료 메시지를 표시합니다.
- 제출 실패: 잠시 후 다시 시도하라는 안내를 표시합니다.
- 개인정보 수집 동의 누락: 제출하지 않고 동의가 필요하다는 안내를 표시합니다.

### 일정 영역

- 일정 0개: 운영자가 일정을 준비 중이라는 문구를 표시합니다.
- 일정 마감: 문의는 가능하지만 확정이 아니라는 문구를 표시합니다.

### 관리자 화면

- 접근 보호 실패: 관리자 화면 또는 문의 목록을 보여주지 않고 접근 권한이 없다는 안내를 표시합니다.
- 문의 0개: 아직 접수된 문의가 없다는 빈 상태 문구를 표시합니다.
- 데이터 로딩 실패: 문의 목록을 불러오지 못했다는 안내를 표시합니다.

| NFR-003 | 개인정보 입력 항목은 MVP에 필요한 최소 범위로 제한해야 합니다. | 문의 폼에는 이름, 전화번호, 희망 일정, 문의 내용, 참여 인원 외 불필요한 개인정보를 요구하지 않습니다. |
| NFR-004 | 관리자 화면은 단순 확인 용도로 제한하되 최소 접근 보호를 적용해야 합니다. | 검색, 통계, 권한 관리, 상태 변경, 자동 응대 기능은 포함하지 않고, 접근 키 또는 단일 비밀번호 없이는 문의 목록에 접근할 수 없습니다. |
| NFR-005 | 서비스는 배포 후 기본 접속 안정성을 가져야 합니다. | 배포 URL 접속 시 랜딩 페이지가 열리고, 새로고침해도 주요 화면 접근이 가능합니다. |
| NFR-006 | 데이터 로딩 또는 제출 실패 상황을 사용자에게 알려야 합니다. | 실패 시 빈 화면으로 멈추지 않고 다시 시도 안내 또는 실패 안내 문구가 표시됩니다. |
| NFR-007 | Supabase 접근 키는 공개 클라이언트에 노출 가능한 값과 서버 전용 값을 구분해야 합니다. | 서비스 역할 키나 관리자용 비밀 값은 브라우저 코드에 포함되지 않고 서버 환경변수에서만 사용됩니다. |
| NFR-008 | 개인정보 보관 기준을 안내해야 합니다. | 문의 폼 또는 하단 안내 영역에 수집 목적, 보관 기간, 삭제 요청 방법이 표시됩니다. |

## 화면 요구사항

### 랜딩 페이지

- 모바일 우선으로 구성합니다.
- 첫 화면에서 워크숍명, 한 줄 소개, 신청 버튼을 확인할 수 있어야 합니다.
- 정보는 소개, 일정, 문의 폼 순서로 자연스럽게 이어져야 합니다.

### 관리자 화면

- 접수 문의 목록을 표 또는 리스트 형태로 표시합니다.
- 모바일에서도 최소한 이름, 전화번호, 희망 일정은 읽을 수 있어야 합니다.
- 접근 키 또는 단일 관리자 비밀번호 없이는 문의 목록을 표시하지 않습니다.
- 고급 대시보드처럼 통계 카드나 그래프를 만들지 않습니다.

### 운영 체크리스트 화면 또는 영역

- 운영자가 워크숍 전 확인할 항목을 목록 형태로 표시합니다.
- 정적 목록으로 제공하며 체크 상태 저장, 항목 수정, 사용자별 체크리스트 관리는 만들지 않습니다.

## 테스트 시나리오

### 참여자 문의 제출

예시:

- 이름: 김민지
- 전화번호: 010-1234-5678
- 희망 일정: 6월 10일 오후 2시
- 문의 내용: 초보자도 참여 가능한가요?
- 개인정보 수집 동의: 체크

기대 결과:

- 제출 후 접수 완료 메시지가 표시됩니다.
- Supabase 문의 테이블에 김민지 문의가 저장됩니다.
- 접근 보호를 통과한 관리자 화면 문의 목록에 김민지 문의가 표시됩니다.

### 필수값 누락

예시:

- 이름 입력
- 전화번호 미입력
- 희망 일정 선택
- 개인정보 수집 동의 체크

기대 결과:

- 폼이 제출되지 않습니다.
- 전화번호 입력이 필요하다는 안내가 표시됩니다.

### 개인정보 수집 동의 누락

예시:

- 이름 입력
- 전화번호 입력
- 희망 일정 선택
- 개인정보 수집 동의 미체크

기대 결과:

- 폼이 제출되지 않습니다.
- 개인정보 수집 동의가 필요하다는 안내가 표시됩니다.

### 일정 확인

예시:

- 일정 3개가 등록된 상태

기대 결과:

- 참여자는 각 일정의 날짜, 시간, 장소, 가격, 모집 인원을 확인할 수 있습니다.
- 희망 일정 선택 항목에 등록된 일정이 표시됩니다.

### 문의 없는 관리자 화면

예시:

- 접근 보호를 통과했고 접수된 문의가 없는 상태

기대 결과:

- 빈 화면이 아니라 아직 접수된 문의가 없다는 문구가 표시됩니다.

### 관리자 화면 접근 보호

예시:

- 접근 키 또는 단일 관리자 비밀번호 없이 관리자 화면에 접속한 상태

기대 결과:

- 문의 목록이 표시되지 않습니다.
- 접근 권한이 없다는 안내가 표시됩니다.

### 운영 체크리스트 확인

예시:

- 운영자가 워크숍 전 관리자 영역에 접속한 상태

기대 결과:

- 장소 예약, 준비물, 참여자 연락, 사전 안내 메시지, 당일 진행 순서 항목을 확인할 수 있습니다.
- 체크 상태 저장, 항목 수정, 사용자별 체크리스트 관리는 제공되지 않습니다.

## 구현 우선순위

### 1순위

- 랜딩 페이지
- 일정 표시
- 문의 폼
- Supabase 문의 데이터 저장
- 접수 완료 메시지
- 개인정보 수집 동의 및 민감정보 입력 방지 안내

- 단일 관리자 접근 보호

### 3순위

- 운영 체크리스트
- 모바일 화면 다듬기
- 배포 전 문구 정리

- 관리자 문의 목록 화면 작성
- 관리자 접근 보호 적용

### 3일차

- 운영 체크리스트 작성
- 모바일 반응형 확인
